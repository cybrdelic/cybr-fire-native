# CYBR FIRE V8 — fine-transport detail rebuild

This is an extension of the attached V7 source, not an unrelated generated movie.
See `docs/DETAIL_REBUILD.md` for the numerical method, ownership, and limits.

The main capture uses a 99,090,432-cell fine **scalar** grid and a 7,168,000-cell
parent velocity/pressure grid. The number of scalar cells must not be presented
as the number of cells in a full fine-grid fluid solve.

Requirements: Python 3.10+, NumPy, SciPy, Pillow, Linux/EGL with OpenGL 4.5, and FFmpeg. The bounded-slab readback path
uses `glGetTextureSubImage`; a bare OpenGL 4.3 context is not enough.
The completed measurements identify the actual adapter. The large fine run approached a 4-GiB container memory limit. Allow
at least 6 GiB of free RAM on a normal software-rendering machine; a dedicated hardware
adapter may impose different combined GPU/host memory requirements.

Run the new manufactured-data checks:

```sh
python -m pip install -r requirements.txt
OPENBLAS_NUM_THREADS=1 LP_NUM_THREADS=4 python tests/test_detail.py
```

The legacy parent engine's tests remain in `tests/`. Run them separately with
`python -m cybrfire test`; do not infer that older evidence files describe this
branch without an explicitly recorded new run.

The parent-cache builder imports the previous V7 starting state and advances it
with the original V7 solver using a smaller fixed tick. The initial-condition
transfer is not an equivalent restart. The fine capture then consumes the
complete parent cache. These runs must be sequential on a 4-GiB machine.

```sh
# Input is the complete V7 ZIP already supplied in this conversation.
# The ZIP must contain CYBR_FIRE_V7/cache/v7-start.npz.
python tools/build_parent_cache.py /path/to/CYBR_FIRE_V7_complete.zip
python tools/capture_detail.py --parent-cache cache/parent --out captures/v8
```

`capture_detail.py` publishes individual lossless frames and a flushed journal
as it works. It marks the capture complete only after encoding and decoding the
MP4. Its default camera traces at 2160 x 3840 without image upscaling or image-frame
interpolation. Parent numerical velocities are time-interpolated as part of the
one-way coupling, which is distinct from interpolating video frames. The file `capture.json` records exact dimensions, steps, timings,
fields, method limitations, source hash, and adapter.

Reproduction needs the V7 starting-state archive (or an explicitly constructed
alternative parent cache). The two scalar textures use FP32 storage. The prescribed-velocity sampling
caches use FP16; this is a disclosed memory/precision tradeoff. Fine heat does
not feed back into the parent flow. Solid masks and embers are not included in
this focused free-space detail capture.

The source ZIP alone contains no hidden pre-rendered
fire images or downloaded stock footage.

## Persistence boundary

The frame journal preserves completed image files, not a restartable fine-field
checkpoint. The fine-stage arrays must currently be recomputed after a failed
process. The parent engine retains its existing checkpoint implementation. The
project bundle includes the actual starting state; derived parent snapshots are
regenerated by the supplied script, not silently downloaded.
